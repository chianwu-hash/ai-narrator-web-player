# 功能待辦紀錄

最後更新：2026-07-25

本文件記錄播放器已完成、暫不做與後續可排程的功能。它不是法律授權文件，只是開發與管理維護用的工作紀錄。

## 已完成

### 1. 許願池

狀態：已完成 MVP。

已包含：

- 前台「許願池」入口。
- 使用者匿名送出想聽的書、作者與推薦理由。
- 前台公開顯示其他人的許願內容。
- SVG 水池視覺。
- 以 Open Library 查找可用封面，將封面做成書本卡片放入池中。
- 後台 `/admin/wishes` 管理願望狀態。
- 不要求使用者記名，也不記錄使用者聽了什麼書。

參考文件：

- `docs/WISH_POOL.md`
- `supabase/migrations/202607170004_book_wishes.sql`

### 2. 書籍 / 單集留言

狀態：已完成 MVP，且需求已從「只給管理者看」調整為「前台公開」。

已包含：

- 書籍留言。
- 單集留言。
- 留言類型：感想、重大錯誤回報、其他。
- 前台所有使用者可看到留言。
- 同一瀏覽器可編輯或刪除自己的留言。
- 管理者可在 `/admin/comments` 調整狀態或刪除留言。
- 後台不記錄播放進度，不追蹤使用者聽了什麼書。

參考文件：

- `docs/ADMIN_COMMENTS.md`
- `supabase/migrations/202607170002_content_comments.sql`
- `supabase/migrations/202607170003_comment_ownership.sql`

### 3. 播放器風格自選

狀態：已完成 MVP。

已包含：

- 使用者可自行選擇播放器風格。
- 初始風格：書房綠、紙頁暖、夜讀墨。
- 風格偏好保存在本機。
- 若使用者已開啟跨設備同步，`themeId` 會跟著同步。
- 風格不影響播放進度、最愛、留言或許願池。

### 4. 跨設備同步

狀態：已完成 MVP。

已包含：

- 匿名收聽檔案。
- 第一台設備可開啟同步。
- 已同步設備可產生配對碼。
- 新設備或新瀏覽器輸入配對碼後同步播放進度、最愛、倍速、最後播放集數與風格。
- 不把共用邀請碼當成個人進度身份。

參考文件：

- `docs/SUPABASE_SYNC.md`
- `supabase/migrations/202607170001_sync.sql`

### 5. 設備使用監控

狀態：已完成 MVP，正在觀察實際資料。

已包含：

- 前台登入後定期送出匿名設備活動。
- 後台 `/admin/devices` 顯示總設備數、24 小時活躍、7 天活躍與匿名設備列表。
- 不記錄書名、單集、播放進度或使用者姓名。

參考文件：

- `docs/DEVICE_MONITORING.md`
- `supabase/migrations/202607170005_device_activity.sql`

### 6. 後台導覽與總覽

狀態：已完成基礎版。

已包含：

- `/admin` 管理總覽。
- 後台共用導覽列。
- 後台「回播放器」連結。
- 前台「說明」與「管理」入口。
- `/help` 登入後說明頁。
- 總覽顯示新留言、新許願與 24 小時活躍設備數。

### 7. 首頁內容探索與匿名播放排行

狀態：已完成。

已包含：

- 最近新增：依 Drive 書籍資料夾更新時間排序。
- 最近播放：依目前使用者的本機進度排序。
- 熱門書籍與熱門單集：只記錄內容層級的匿名累積播放次數。
- 排行不記錄使用者、設備、IP 或個人播放進度。

參考文件：

- `docs/PLAY_STATS.md`
- `supabase/migrations/202607180001_content_play_stats.sql`

### 8. 管理後台書封整理

狀態：已完成。

已包含：

- `/admin/covers` 顯示 Drive 書庫及目前封面。
- 管理者可上傳小於 5 MB 的 JPG、PNG 或 WebP。
- 有封面時更新原封面；沒有時在該書資料夾新增 `cover.*`。
- 更新後以 Drive 修改時間與大小更新封面版本，避免瀏覽器沿用舊快取。
- 只允許根目錄直接子資料夾中的書籍，不會移動或刪除其他 Drive 檔案。

部署時若要使用此功能，service account 對指定書庫根資料夾必須有編輯權限；只使用播放功能則檢視者即可。

## 暫不做

### 公開徵集或投票

許願池只作為私人需求收集，不做公開投票、排名或大規模徵集。

### 記錄使用者聽了什麼書

設備監控只統計匿名設備活動，不記錄書名、單集、播放時間軸或閱讀偏好。

### 使用者帳號系統

目前維持「邀請碼 + 匿名同步檔案 + 配對碼」模式，不建立個人帳號、Email 登入或 OAuth。

### 後台直接修改邀請碼

邀請碼仍由 Vercel 環境變數管理。這比較麻煩，但安全邊界清楚。若未來要做後台更換邀請碼，需要另外設計權限與審計紀錄。

## 建議下一步

### 1. 確認 Supabase migration 都已執行

依檔名順序確認 `supabase/migrations/` 內六個 migration 都已執行。缺少個別 migration 時，基本書庫與播放仍可使用，但對應的同步、留言、許願、設備監控或熱門排行會停用。

### 2. 實機觀察設備監控

用手機、桌機、不同瀏覽器登入後，觀察 `/admin/devices` 是否出現匿名設備紀錄。

需要確認：

- iOS Safari 是否會送出活動。
- Chrome / Edge 是否分別被視為不同設備。
- 清除網站資料後是否會被視為新設備。

### 3. 同步 Telegram 群組 `/help`

狀態：標準文案已準備；是否已套用到正式運行中的 bot，仍需在 bot 的實際部署來源確認。網站程式不會自動修改 Telegram bot。

標準文案已整理於：

- `docs/TELEGRAM_HELP.md`

確認 Telegram bot 的實際 `/help` 實作後，應同步目前網站說明：

- 網站網址。
- 邀請碼用途。
- 管理者碼只供後台使用。
- 不私自分享邀請碼與內容。
- 管理者會不定期更換邀請碼。
- 本網站旨在個人研究與導讀，不取代原書閱讀。
- NotebookLM 目前 4 個帳號輪值，一天可規劃 4 本書。

### 4. 邀請碼更換紀錄

可先不用做成正式後台功能，但建議以文件方式記錄：

- 更換日期。
- 更換原因。
- 是否已通知親友。
- 是否需要讓舊 session 失效。

### 5. 管理後台的低成本改善

可排在後續小任務：

## 長期才考慮

### 音訊流量與成本優化

正式音訊 bytes 已規劃改由 Cloudflare Worker 透過短效簽章 URL 與 Range request 串流，Vercel 僅保留登入、書庫 API、簽 URL、token broker 與未設定 Worker 環境的回退 route。後續應依 `docs/VERCEL_HOBBY_TRAFFIC_FIX.md` 驗收 Worker Analytics、Vercel `/api/audio/[fileId]` 是否不再承擔 production bytes，以及 iOS Safari／Android Chrome 實機播放。

### 更完整的管理稽核

若使用者範圍擴大，後台操作可以增加稽核紀錄，例如誰刪了留言、何時更改邀請碼。但這會引入更多管理資料，應確認必要性後再做。
